## Проверки без запуска оболочки

Нужны Python 3 и Node.js 22.16+ (используется `import.meta.dirname`).

```sh
python3 -m compileall -q .
python3 build-pet-worker.py --check
node tests/tube-and-family.mjs
node tests/bubble-family.mjs
node tests/duration-cache.mjs
node tests/analysis-policy.mjs
python3 tests/analysis-identity.py
python3 tests/audio-recovery.py
python3 tests/service-recovery.py
```

Проверки подтверждают одну геометрию трубы в обоих направлениях, движение головы по физической кривой, изоляцию следа между персонажами/транспортами, криволинейные локальные/пузырьковые маршруты, самостоятельные путешествия близнецов, возврат и слияние только после фактического сближения, а также случай с пластиковой перегородкой. Они не подменяют визуальные проверки на GPU.

В native-ветке `python3 tests/installer.py` проверяет, что shim не меняет файлы и не очищает данные. Тест установки с адаптерами на временной копии штатной оболочки находится в стабильной ветке v2.

## WorkerScript

`PetPlannerWorker.mjs` — генерируемый пакет. Правьте исходные `GlassRoutes.js`, `PetPhysics.js`, `PetNavigation.js`, `PetMotion.js` и `BubbleTransfer.js`, затем:

```sh
python3 build-pet-worker.py
python3 build-pet-worker.py --check
```

Расширение `.mjs` важно для изолированного Qt WorkerScript. Сохраните адресацию запросов по generation/request/actor; ответы предыдущей сцены или другого огонька не должны менять текущий маршрут.

## Шейдеры

Нужен `qsb` из Qt Shader Tools, соответствующий целевой версии Qt. Исходные `.frag` включены; `.qsb` поставляются для удобства установки. Например:

```sh
/usr/lib/qt6/bin/qsb --glsl '100 es,120,150' --hlsl 50 --msl 12 \
  -o wallpaper-wire-glow.frag.qsb wallpaper-wire-glow.frag
```

При изменении shader uniform меняйте QML-параметры и пересобирайте QSB вместе. Проверяйте альфа-смешивание, ореол поперёк узкой трубы, след на входе/выходе и отображение под перекрывающими слоями. Логика движения должна использовать ту же физическую кривую, что и изображение трубы.

## Воспроизвести демонстрации

Нужна работающая графическая сессия с Quickshell и аппаратным Qt Quick renderer, а для проверки PNG — Python Pillow. Рендерер открывает отдельное тестовое окно, работает с временной копией компонентов и не запускает запись Spotify/модели/штатный сервис оболочки.

```sh
python3 tools/render-demo.py dock /tmp/dock-frames
python3 tools/render-demo.py wallpaper /tmp/wallpaper-frames
python3 tools/render-demo.py voices /tmp/voice-frames
python3 tools/render-demo.py settings /tmp/settings-frames
```

Проверяющий скрипт требует завершённую последовательность PNG, подходящие размеры, достижение обязательных состояний и видимое отличие между ними. Откройте `contact-sheet.jpg` для ручной проверки и используйте `--against /tmp/проверенный-эталон` для сравнения следующего прогона. `--keep-failed /tmp/отклонённые-кадры` сохраняет материалы диагностики отдельно от результата.

PNG-кадры можно собрать FFmpeg: док/голоса — 20 fps, обои — `100/7` fps. Сцены используют тестовые слова и синтетический спектр; раннее разделение питомца специально вызвано сценарием демонстрации. Не измеряйте по ним нагрузку установленного shell.

## Изменять работающую установку

В ветке v3 обновляйте папку плагина через менеджер после завершения аудиозаданий; install.py здесь не устанавливает компоненты. В стабильной ветке v2 для обновления с сохранением данных применяется `python3 install.py --repair`. Проверяйте IPC обоих мониторов и журнал: список плагинов сам по себе доказывает только обнаружение манифеста, но не успешную отрисовку дока.

В первоначальной публикации выполнены: регрессии JS, соответствие worker-пакета, изолированный тест установки и repair, проверка Python, визуальная проверка демонстраций и фактическая загрузка адаптеров на двух мониторах. Универсальный прогон всех моделей на чистой системе в CI не выполняется.

### Проверки отказов настроек и renderer

При запущенном Wayland/Hyprland, без остановки основной оболочки:

```sh
python3 tests/settings-recovery.py
python3 tests/renderer-recovery.py
python3 tests/capture-budget.py
```

Первый тест проверяет watchdog 1,6 с, отсутствующий телефон, испорченный QSB, software backend, закрытие в ожидании и устаревший callback после повторного открытия. Второй запускает раскрытый док с повреждёнными шейдерами и software backend: корпус, текст и управление сохраняются, капсулы переходят на Canvas. Третий подставляет недоступный источник в настоящий capture delegate, проверяет остановку после четырёх попыток и новый бюджет после повторной активации. Это контролируемая ошибка источника, а не полная проверка всех комбинаций GPU/драйверов. Тесты создают временные окна и не меняют настройки или пользовательские записи.

Захват получает не больше четырёх попыток на контекст окна. После исчерпания бюджета `unavailable` сохраняется: переход дока на непрозрачную поверхность не снимает demand и не пересоздаёт делегат. Обновление кадров здоровых окон в этом режиме прекращается. Новое окно/новая поверхность получает новый бюджет; скрытие и повторное раскрытие или `qs -c sekaipop ipc call dockcapture-<monitor> retry` позволяют явно повторить отказавший захват. Команда ограничена одним запросом за две секунды. Автоматического опроса неисправного контекста по кругу нет.

`python3 tests/capture-recovery.py` проверяет также переход на настоящий Toplevel тестового окна и освобождение при скрытии. Для такого теста сначала нужно показать окно и дать его scene graph инициализироваться; раннее создание ScreencopyView у обычного Qt Window может остановить инициализацию буферов теста. Документация API: [ScreencopyView](https://quickshell.org/docs/v0.3.0/types/Quickshell.Wayland/ScreencopyView/). Наличие `hasContent`, а не выдуманное свойство готовности контекста, разрешает последующие `captureFrame()`.

В `rendererStatus()` отдельно показываются доступность шейдера, фактический режим поверхности и причина отказа захвата. Фикстура полного дока проверяет: отказ → непрозрачный режим без сброса ошибки → новая рабочая поверхность → возврат стекла. Физическое отключение GPU и все сочетания драйверов этим тестом не проверяются.

`python3 tests/palette-status.py` проверяет JSON-статус Music Palette на отдельной D-Bus-сессии с подставленным IPC. Сам текст «Ожидание музыки» может оставаться одинаковым до и после истечения задержки; флаг active всё равно должен смениться. Тема основной оболочки в этом тесте не меняется.

### Выбор провайдера (INT-04)

После применения предложенного API-патча к тестовому checkout оболочки:

```sh
node tests/extension-providers.mjs /path/to/shell/sekaipop
python3 tests/provider-handoff.py /path/to/shell/sekaipop
```

Проверяются функции из фактического результата применения патча: отключённый первый кандидат, несколько готовых провайдеров, сохранённый выбор, отказ Service, удалённый/недоступный предпочтительный провайдер, некорректный выбор и отсутствие всех провайдеров. QML-тест меняет провайдера без изменения active Loader и проверяет пересоздание компонента и освобождение старой аренды. Логика в `integration/ExtensionProviders.js` должна совпадать с добавляемым патчем файлом оболочки; тест это проверяет.

### Аудиоконтекст, тишина и пауза (AUD-02/AUD-08)

```sh
python3 tests/media-context.py
python3 tests/media-context.py --palette
python3 tests/palette-context.py
```

QML-фикстура использует два тестовых QObject-плеера, настоящий Service и бесшумный тестовый процесс спектра. Проверяются одновременно играющие источники, выбор последнего старта, пауза выбранного при продолжающем играть втором, различие Stopped/Paused, смена epoch, исчезновение плеера, команды управления и ограничения canControl. Нулевой спектр не меняет выбранный Playing/карточку и не выключает захват. `--palette` добавляет настоящий обработчик обложек с подставленным theme IPC; второй тест проверяет частичные записи в pipe, один владелец аренды при смене источника и освобождение при EOF. Реальный звук и тема пользователя тестами не меняются.

`modules.media` содержит playerId, trackId, epoch, state и mode; `modules.audio.signal` различает unknown / silence / audible / released. Цифровая тишина оставляет аудио включённым и музыкальную поверхность выбранной, но амплитуды визуализатора/бокового света равны нулю. Pause/Stopped/исчезновение выбранного плеера снимают demand и освобождают CAVA: капсулы и свет затухают своими существующими анимациями, прогресс/текст останавливаются, обойный питомец переходит к спокойному движению; временные цвета возвращаются после musicPaletteStopDelay. Сохранение карточки при разных видах завершения отдельно относится к MED-08.

`MediaContext.trackId` использует DBus name и opaque uniqueId плеера (при его отсутствии — доступную метку трека), поэтому смена обложки не перезапускает музыкальный epoch. Источник API и ограничений MPRIS: [Quickshell MprisPlayer](https://quickshell.org/docs/v0.3.0/types/Quickshell.Services.Mpris/MprisPlayer/).
