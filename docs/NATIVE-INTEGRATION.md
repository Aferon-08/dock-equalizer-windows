# Предварительная версия 3.0.0-rc.4 и API расширений

Это предварительная версия. **На официальном SekaiPOP commit e629dfe необходимых точек расширения ещё нет.** Плагин не объявляется готовым для Reviewed list до принятия соответствующего API сопровождающим SekaiPOP.

## Что изменилось

Плагин больше не патчит файлы оболочки, не запускает install.py при загрузке и не сбрасывает записи при обновлении. Используются три входных компонента: Dock.qml, Wallpaper.qml и Settings.qml. Их создаёт оболочка и передаёт `host` с темой, геометрией и состоянием. install.py оставлен только как сообщение о новом способе установки; он ничего не изменяет.

В `plugin.json` объявлены `extensions: ["dock", "wallpaper", "settings"]`. Возможности определяются по `host.capabilities`, а не только номеру `VERSION=1.0.0`: номер версии у разных обновлений SekaiPOP одинаковый. При отсутствии API плагин уведомляет о несовместимости, вместо скрытого запуска установщика.

## Патч для автора оболочки

[`integration/sekaipop-native-extensions.patch`](../integration/sekaipop-native-extensions.patch) подготовлен относительно официального commit **e629dfed4781ecc5bf7eeecad28787462dc1e114**. Он не привязан к id данного плагина. Патч добавляет:

- Декларацию и валидацию surfaces в манифесте.
- Хосты дока, обоев и пользовательской страницы настроек.
- Реестр настроенных прямоугольников виджетов в оболочке.
- Явный набор capabilities; управление жизненным циклом поверхностей при загрузке/удалении.
- API временной музыкальной палитры с восстановлением исходной палитры и истечением аренды.

В исходном checkout SekaiPOP для рассмотрения:

```sh
git switch --detach e629dfed4781ecc5bf7eeecad28787462dc1e114
git apply --check /path/to/sekaipop-native-extensions.patch
git apply /path/to/sekaipop-native-extensions.patch
```

Это изменение **самой оболочки**, которое должен рассмотреть её автор. Плагин не выполняет эти команды. Нельзя гарантировать сохранение локального патча после обновления на непатченную официальную оболочку. Надёжное решение — принятие API upstream, а не автоисправление файлов сторонним плагином.

После обновления SekaiPOP до `e629dfe` API снова восстановлен на машине владельца; исходные файлы оболочки и прежний плагин сохранены в `~/.local/state/sekaipop/dock-equalizer-backups/native-api-*`.

## Проверить предварительную версию

Нужен SekaiPOP с этим API. Скопируйте содержимое папки из архива в `~/.config/sekaipop/plugins/dock-equalizer/` и перезапустите оболочку. Сохранённые настройки, записи и разметки хранятся отдельно. [Предварительный релиз](https://github.com/Aferon-08/sekaipop-dock-equalizer/releases/tag/v3.0.0-rc.4)

После принятия API и выпуска плагина в основной ветке штатный менеджер сможет клонировать/подключать этот же формат одной кнопкой без специальных шагов. Устанавливать нынешнюю ветку main через менеджер ради теста v3 пока не следует: main содержит стабильную v2 с прежними адаптерами.

```sh
qs -c sekaipop ipc call dockequalizer status
```

`nativeIntegration: true` означает, что доступна хотя бы одна штатная поверхность. `modules.host.capabilities` и `missing` показывают каждую возможность отдельно: отсутствие API обоев или настроек не выключает док. Версии поверхностей проверяются по именам capabilities; временная палитра необязательна. Проверьте также статусы `docklyrics-<monitor>` и `proceduralwallpaper-<monitor>`: обнаружение одного манифеста не доказывает успешную отрисовку.

## Каталог

После рассмотрения API и проверки установки понадобится отдельная заявка в SekaiPOP: запись в `plugins.json` и синхронное изменение раздела Plugins README оболочки. До назначения версии, включающей API, нельзя честно указать минимальную совместимость просто как `1.0.0`. Заявка/PR от имени владельца автоматически не отправлялись.

## Производительность

Конец каждой партии теперь вычисляется по сохранённым границам таймлайна, вместо повторного разбора всей песни на каждом кадре. Скрытые голосовые области и одиночная лирика под многоголосным видом не держат активные строки. Результаты финалов сохранены; это оптимизация отображения, не новая модель распознавания певцов.

На частной копии лирики указанного владельцем трека: медиана отдельной сцены ~35 → ~17 мс; в оболочке на двух мониторах после прогрева — ~14 мс, p95 ~27 мс. Эти числа описывают конкретный прогон, не обещают одинаковой частоты кадров на любом GPU и не включают тяжёлый анализ аудио. Текст/записи песни в репозиторий не включены.

## Встроенная палитра музыки (rc.3)

Music Palette теперь входит в Dock Equalizer: один фоновый процесс `music-palette.py`, настройки **«Музыкальная палитра → Цвета системы по обложке»** и **«Задержка восстановления цветов»**. Размещать информационную карточку на рабочем столе не нужно. При отсутствии `transient-palette-v1` модуль отмечается как `unsupported`, док и обои продолжают работать независимо. Статус: `modules.palette` в `dockequalizer status`.

Перед переходом отключите старый отдельный Music Palette, чтобы два процесса не боролись за палитру:

```sh
qs -c sekaipop ipc call plugins set music-palette enabled false
```

Его каталог и сохранённые настройки можно оставить для отката. На машине владельца переключение выполнено с резервной копией. Новый модуль использует ту же временную аренду, кеширует обложки, отбрасывает устаревшие загрузки и сохраняет активную палитру при пустой обложке или ошибке HTTP. Только настоящая пауза/остановка по истечении заданной задержки возвращает исходные цвета. При аварийной смерти процесса аренда истекает за 5 секунд. Цвета музыки не записываются в постоянную тему.

**Обновления официальной оболочки всё ещё могут удалить локальный API.** Это ограничение самой интеграции, а не признак выключенной карточки плагина. Плагин не подменяет обновлятор и не правит файлы оболочки при загрузке. Текущий патч проверяется относительно указанного выше commit; перед переносом на другой commit нужны проверка патча, резервная копия и запуск с контролем ошибок.

## Несколько расширений одной поверхности

В предложенном host API выбор дока/обоев теперь явный. В штатной карточке каждого плагина с такой поверхностью показывается выбранный провайдер и кнопки **Use this plugin** / **Automatic choice**. При автоматическом выборе несколько кандидатов сопровождаются сообщением о конфликте. Отключённые плагины, ещё не готовые состояния и плагины с отказавшим Service пропускаются; без подходящего кандидата используется штатный док/фон.

```sh
qs -c sekaipop ipc call plugins providers
qs -c sekaipop ipc call plugins provider dock dock-equalizer
qs -c sekaipop ipc call plugins provider wallpaper dock-equalizer
qs -c sekaipop ipc call plugins provider dock auto
```

Предпочтение сохраняется в `plugins.extensionProviders` обычных настроек оболочки. Если выбранный плагин выключен/удалён/не загрузился, другой доступный провайдер используется с явной причиной `preferred-unavailable`; при возвращении выбранного предпочтение снова действует. Переключение меняет компонент в Loader и освобождает аренду прежнего провайдера. Для настроек каждой карточки остаётся её собственный Settings.qml.

## Общий музыкальный контекст (native-media-v1)

Дополнение к API связывает все доки одного расширения с `Service.mediaContext`. Он предоставляет стандартные поля media source (`player`, `present`, `playing`, `title`, `artist`, `artUrl`, `volumeAvailable`) и методы управления. Если провайдер не предоставляет этот объект, штатный MediaSource остаётся доступен. Новая capability `native-media-v1` обозначает поддержку этого подключения; при старом host статус `modules.media.integration` отмечается как degraded с просьбой обновить патч. Остальные поверхности продолжают работать.

В Dock Equalizer выбор теперь один на все мониторы: последнее приложение, действительно перешедшее в Playing, сохраняется и на паузе, пока остаётся доступным с треком. Если такого выбора нет, берётся играющий плеер, затем плеер с названием трека; исходный выбор при нескольких плеерах детерминирован по DBus name. Исчезнувший плеер освобождает выбор. Ручное закрепление и исключения относятся к MED-01 и пока не реализованы.

Этот же контекст управляет звуковым захватом, обойными эффектами и Music Palette. Обработчик обложек получает JSON через stdin и не выбирает другой MPRIS-плеер самостоятельно. Переключение плеера сохраняет владельца временной палитры, а пауза выбранного приложения восстанавливает исходную тему после настроенной задержки, даже если другое приложение продолжает играть. Во время задержки статус палитры — holding; при ещё не подтверждённой смене трека/плеера — syncing.

**Режим звука сейчас system-output.** Метаданные и Playing/Pause относятся к выбранному плееру, но спектр поступает со всего системного выхода. Уведомления и другие приложения могут влиять на него, пока выбранная музыка играет. Это не изоляция аудиопотока приложения; выбор такого режима остаётся задачей AUD-09.

Поля playerId/trackId статуса палитры подтверждают принятый обработчиком контекст. При загрузке следующей обложки предыдущая палитра намеренно сохраняется до готовности новой: active обозначает действующую временную аренду, а не обещает мгновенную загрузку изображения. Устаревшие результаты не подменяют выбранную обложку.
