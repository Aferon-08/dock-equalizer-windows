# План переноса саундбара на Windows 11

Цель — выпустить самостоятельное приложение для Windows 11 с собственным
окном, визуализатором звука, управлением воспроизведением, лирикой и настройками.
Первая целевая платформа — Windows 11 x64. По согласованному уточнению
код первого этапа готовим в текущей облачной среде. Приёмка требует
сборки и запуска `.exe` на Windows 11.

Исходная точка — `main` на коммите `50d08a9`, плагин версии `2.23.0`.
Архитектура нового приложения — Qt 6 / Qt Quick / QML для интерфейса,
C++ и Windows API для платформенных функций, CMake и MSVC для сборки.
Анимации, расчёты и исходники шейдеров переносим из существующего проекта.

## 1. Первый Windows `.exe` с демонстрационной сценой

1. На Windows 11 x64 проверить MSVC, Windows SDK, CMake и Qt 6, включая
   Quick Controls, Shader Tools и SVG. Для первой сборки использовать
   Qt 6.8.2 MSVC x64 и Visual Studio 2022.
2. Добавить проект CMake и Windows preset. Создать точку входа, собственное
   окно Qt Quick и QML-модуль. Включить в сборку только ресурсы, которые
   нужны автономному доку.
3. Использовать данные из [демонстрации дока](../tools/demo-dock.qml) как
   основу. Передавать тестовую обложку или заглушку, синтетический стереоспектр,
   прогресс и текст. Сохранить пропорции, цвета и основные анимации.
4. Заменить зависимости QML от Quickshell в загружаемой сцене. Подставить
   собственный фон вместо `SettingsUnderlay`, сохранить скругление обложки
   через компоненты Qt Quick, перенести IPC и запускаемые процессы за пределы
   сцены. На этом этапе внешние сервисы заменяют тестовые модели.
5. Собрать исходные `.frag` в QSB версией инструментов из того же Qt SDK.
   Проверить загрузку QML и шейдеров через Direct3D 11. Собрать папку запуска
   с Qt DLL, QML-модулями и плагинами.

Приёмка первого этапа. `.exe` запускается на Windows 11, показывает компактное
и раскрытое состояние, спектр, прогресс и анимацию лирики на тестовых данных.
В журнале отсутствуют ошибки загрузки QML и шейдеров. Упакованный запуск
обходится без SekaiPOP, Quickshell, Python, Node.js и установленного Qt SDK.

### Команды первого запуска на Windows

Из корня репозитория в PowerShell. Нужны Visual Studio 2022 с набором
«Разработка классических приложений на C++», Windows SDK, CMake 3.25+
и Qt 6.8.2 для MSVC 2022 x64 с Qt Shader Tools. Подставьте свой путь
к SDK, если он отличается.

```powershell
$qtSdk = 'C:\Qt\6.8.2\msvc2022_64'
$env:Path = "$qtSdk\bin;$env:Path"
cmake --preset windows-msvc-x64 "-DCMAKE_PREFIX_PATH=$qtSdk"
cmake --build --preset windows-msvc-x64 --parallel
ctest --preset windows-msvc-x64
cmake --install out/build/windows-msvc-x64 --config Release
& .\out\stage\windows-msvc-x64\SekaiSoundbar.exe
```

Панель открывается у верхней кромки основного экрана. Для тестового трека
доступен запуск с аргументом `--demo-preview`.
Щелчок по панели раскрывает лирику, правый щелчок открывает меню с выходом.
Тест проверяет размещение панели и отрисовку компактного и раскрытого видов.
Для проверки поставки запустите собранную папку
`out/stage/windows-msvc-x64` на Windows 11 без Qt SDK в `PATH`.

## 2. Окно, трей и настройки

- Открывать панель без рамки по центру верхней кромки рабочей области
  основного монитора. Панель находится между рабочим столом и окнами
  приложений и скрывается при активном полноэкранном приложении
  на этом мониторе.
- Учесть рабочую область монитора и DPI. При восстановлении панели фокус
  остаётся в текущем приложении. Прозрачные участки вне панели пропускают
  щелчки. В дальнейшем добавить выбор экрана и положения.
- Добавить трей с показом, скрытием, настройками и выходом, один экземпляр
  приложения и автозапуск по выбору пользователя.
- Перенести применимые параметры, диапазоны, поиск и сброс. Хранить состояние
  в профиле Windows, отдельно от программных файлов.

Приёмка. Положение и настройки переживают перезапуск. После отключения
монитора окно возвращается в доступную область.

### Капля при остановке воспроизведения

Когда плеер сообщает о паузе, док сохраняет текущий вид.
После минуты паузы корпус сжимается в каплю и втягивается за верхнюю
кромку экрана. При остановке трека или исчезновении источника действует
короткая задержка в 600 мс. При возобновлении воспроизведения переход
идёт в обратную сторону. Если музыка возобновится посреди сворачивания,
обратный переход начинается из текущего положения. В скрытом состоянии
панель освобождает область ввода. Значок в трее открывает док и настройки,
пока воспроизведение на паузе.

### Раскрытие дока на рабочем столе

Док расположен в порядке окон Windows между поверхностью рабочего стола
и окнами приложений. `DesktopOverlay` проверяет окна каждые 100 мс и обновляет
положение дока в порядке окон с сохранением фокуса. Видимая часть
дока доступна для кликов. Развёрнутые обычные окна и другие приложения
могут закрывать его. Проверить показ рабочего стола через Win+D и
восстановление положения после перезапуска Проводника.

Для проверки используется **целевая область полностью раскрытой панели**
с учётом размеров лирики, вокальных партий и масштаба экрана. Область
проверяется и в компактном состоянии.

`DesktopOverlay` отслеживает видимые окна над доком на его мониторе,
включая неактивные окна. Для пересечения использовать видимые границы
DWM в физических пикселях. Исключить сам док, его меню, свёрнутые окна,
поверхность рабочего стола и окна других виртуальных рабочих столов.
Периодическая проверка объединяет близкие события при перетаскивании,
изменении размера, сворачивании и смене порядка окон.

1. Полноэкранное приложение на мониторе дока сразу скрывает панель.
2. При остановке музыки действует переход в каплю. После появления
   музыки док возвращается в доступную форму.
3. Во время воспроизведения пересечение с раскрытой областью включает
   компактный вид. Если приложение перекрывает и его, док остаётся
   под этим окном.
4. Когда раскрытая область свободна около 400 мс, док раскрывается.
   Если окно возвращается на середине перехода, анимация сворачивает
   панель с её текущего размера.

Приёмка. При перетаскивании окна через область лирики панель сворачивается
один раз и раскрывается после освобождения места. При максимизации
обычное окно перекрывает док и принимает клики. После его сворачивания
док раскрывается, если музыка играет. Проверить две соседние области
Snap, Win+D, полноэкранный режим, разные DPI и второй монитор.

## 3. Медиасессии и часы воспроизведения

- Получать список GSMTC-сессий, метаданные, обложку, возможности управления
  и позицию через WinRT. По умолчанию следовать активной системной сессии.
  Выбор источника находится в меню по правому щелчку.
- Использовать единые часы для прогресса, текста и анимаций. Учитывать паузу,
  перемотку, скорость и редкие обновления позиции. Отбрасывать результаты
  асинхронных запросов от прежней сессии или трека.
- Считать URL, длительность, обложку и перемотку опциональными. Подстраивать
  доступность кнопок под возможности сессии и результат команды. Громкость
  приложения менять только после надёжного сопоставления аудиосессии.

Приёмка. Spotify, браузер и локальный плеер можно переключать. Метаданные
и команды принадлежат выбранному источнику. Пауза и перемотка корректно
двигают общие часы.

Для проверки на Windows 11 запустите музыку в Spotify или откройте видео
в браузере. Дождитесь появления карточки, затем проверьте паузу,
переключение дорожек и щелчок по полосе прогресса. Через «Источник»
можно закрепить другой плеер или вернуться к системному выбору.
Карточка показывает только те действия, которые поддерживает сессия.
Громкость доступна при точном совпадении идентификатора приложения
и единственной подходящей аудиосессии на устройстве вывода по умолчанию.
Обычный запуск использует реальные медиаданные.

## 4. Системный спектр

- Реализовать WASAPI loopback для общего микса устройства вывода. Вынести
  чтение семплов, приведение форматов, FFT и сглаживание в фоновую обработку.
- Сохранить 32 полосы на канал, диапазон `0–1000` и примерно 30 обновлений
  в секунду. Перенастроить чувствительность и ритм по синтетическим сигналам.
- Отрабатывать тишину, смену устройства вывода, отключение Bluetooth/USB,
  блокировку и выход из сна. Оставить спектр доступным для звука приложений
  без медиасессии.

Приёмка. Тишина гасит спектр, тестовые тоны попадают в нужные каналы
и полосы, а смена устройства восстанавливает реакцию.

Боковые полосы получают спектр общего микса устройства вывода Windows
по умолчанию. WASAPI loopback захватывает звук в памяти, а фоновый поток
рассчитывает по 32 полосы для левого и правого каналов. Наличие медиасессии
влияет на карточку трека, а звуковая анимация следует за самим миксом.

Для проверки включите музыку на устройстве вывода по умолчанию. Сравните
реакцию полос во время музыки и паузы, затем переключите устройство вывода
в параметрах звука Windows и продолжите воспроизведение.

## 5. Лирика, импорт и поиск

- Реализовать локальный импорт LRC и JSON Lyrics Wordtime Extractor схем 1 и 2.
  Использовать ограничения и поведение `wordtime.py` как эталон при тестировании
  импорта в приложении. Проверять длительность, границы таймингов и партии.
- Создать собственный онлайн-провайдер лирики с кешем, отменой при смене трека
  и состояниями отсутствия текста или сети. Сопоставлять по стабильному ID
  при наличии, иначе по метаданным и длительности. При неоднозначности
  предоставить ручной выбор.
- Сохранить подсветку слов, маркер, огонёк, подпевки, несколько голосов
  и финальные состояния. Согласовать отображение с общими часами приложения.

Приёмка. Локальный импорт работает без сети и с путями на кириллице.
Перемотка и пауза синхронизируют подсветку. Старый текст не возвращается после
смены трека.

Локальный импорт доступен через правый клик по доку и пункт «Загрузить
лирику…». Выберите файл для текущего трека. LRC подсвечивает строки, а JSON
Wordtime использует тайминги слов и вокальных партий. Импорт раскрывает
панель лирики, а при смене трека или выборе «Убрать загруженную лирику» текст
сбрасывается. Для построчных таймингов время прыжков маркера и всплесков
приблизительно распределяется по словам внутри строки. Подсветка таких строк
работает по отметкам строк. Для пословных источников эффекты следуют их
временным отметкам.

Поиск использует несколько источников из [LyricsService SekaiPOP](https://github.com/Blapples/SekaiPop/blob/69e1df0f282ca9a5193c1a628b346e5df01c7d93/sekaipop/services/LyricsService.qml).
Better Lyrics, LyricsPlus, LRCLIB, SimpMusic и NetEase Cloud Music опрашиваются параллельно.
Док передаёт названия трека и исполнителя, а источникам, которым это нужно,
также альбом и длительность. Готовые тайминги слов предпочтительнее построчных.
В меню «Поиск лирики» можно выбрать версию, отключить автопоиск и посмотреть
состояние источников с кодами HTTP, этапом тайм-аута и количеством полученных байтов.
В Windows используется системный curl.exe с HTTP/1.1 и закрытием соединения
после ответа. Если передача прервалась, док использует уже полученный полный
JSON либо повторяет запрос через Qt.
Qt также используется, если curl.exe отсутствует или не запускается.
«Поиск лирики» → «Прокси поиска…» позволяет направить оба запроса через
локальный HTTP или SOCKS5-прокси. Варианты INCY подставляют адреса
`socks5h://127.0.0.1:10808` и `http://127.0.0.1:10809`. При выборе SOCKS5
имена сайтов разрешает прокси. Пустое поле возвращает обычные настройки
curl и системные настройки Windows для Qt.
Результаты для треков с известными исполнителем и
длительностью сохраняются локально. У импортированного файла приоритет.

## 6. Дополнительный анализ и запись Spotify

Дальнейшая работа по этому этапу отложена по согласованию. Текущий этап — оформление дока.

- Начать с ручного выравнивания текста по выбранному локальному аудио на CPU.
  Доставлять Python, FFmpeg и модели отдельно с версиями и контрольными
  суммами. Подготовить проверенный набор зависимостей Windows. Текущий
  `triton==3.9.0` указан без условия, Windows-пакетов у этой версии нет.
- Вынести запуск и прогресс из QML в контроллер фоновых задач. Использовать
  UTF-8 и версионированные сообщения с идентификатором задания, тайм-аут,
  отмену и Windows Job Object для завершения дочерних процессов.
- Затем отдельно проверить многоголосный анализ, CUDA и источник YouTube.
  При сбое и отмене сохранять прежнюю разметку.
- Записывать Spotify отдельно от системного спектра через WASAPI process
  loopback. При неоднозначном сопоставлении процесса запись недоступна.
  Для Windows предлагается включение записи по явному выбору пользователя.

Приёмка. После отмены не остаются дочерние процессы. Ошибка анализа не
повреждает сохранённые тайминги. Тест с двумя звучащими приложениями
подтверждает, что в запись попал только Spotify.

### Локальное выравнивание на Windows

Пункт «Выровнять лирику…» открывает выбор аудиофайла и готового текста.
Текст найденной или импортированной лирики подставляется для текущего
трека. Его можно отредактировать перед запуском. Длительность локального
аудиофайла проверяется по медиасессии, когда плеер её сообщает.

При первом запуске «Подготовить модуль» загружает около 450 МБ. Модуль
использует Whisper base, stable-ts 2.19.1, PyTorch CPU 2.7.1 и FFmpeg из
imageio-ffmpeg 0.6.0. Версии и SHA-256 Windows-колёс зафиксированы в
[`cpu-windows.lock`](../windows/alignment/cpu-windows.lock), а хеши модели
и исходных архивов проверяет [обработчик](../windows/alignment/worker.py).
Компоненты и библиотеки Visual C++ устанавливаются в профиль пользователя.
Готовый модуль обрабатывает текст и аудио локально.

Док принимает только проверенный Wordtime JSON и применяет его к тому же
треку. Результат можно сохранить отдельным файлом и импортировать позже.
Прогресс и финальный результат идут через версионированные сообщения
с ID задания. При отмене Windows Job Object завершает Python и его
дочерние процессы.

Переносимая сборка содержит отдельную папку alignment с CPython 3.12.10
x64. Для сборки из исходников в Windows передайте путь к каталогу
`tools` пакета
[python.3.12.10.nupkg](https://www.nuget.org/packages/python/3.12.10)
через `SOUNDBAR_ALIGNMENT_PYTHON` при настройке CMake. SHA-256 пакета
`0eb85c2dfccccf1b17352de4c397f69194035b7d37149eacc16f1147d93de3b8`.

## 7. Стекло и графические эффекты

- Сохранить форму, подсветку корпуса, управление материалом и анимацию
  панели настроек. Проверить полупрозрачный фон и упрощённую отрисовку
  для случаев, когда шейдер или аппаратное ускорение недоступны.
- Отдельно проверить Windows Graphics Capture и передачу текстуры в шейдер.
  Измерить нагрузку, исключить рекурсивный захват окна приложения и обрабатывать
  недоступный источник. Системный фон DWM рассмотреть как отдельный вариант.
- Проверить разные DPI, несколько мониторов, полноэкранные приложения,
  повторное открытие настроек и освобождение ресурсов захвата.

В меню по правому клику пункт «Оформление дока…» открывает настройки
стекла, непрозрачности корпуса, матовости и затемнения лирики и яркости
музыкальной подсветки. Преломление в панели лирики работает с
внутренним изображением дока. Изменения видны сразу и сохраняются в
профиле пользователя. «Сбросить» возвращает параметры Windows-сборки.

Если аппаратный Direct3D 11 недоступен, приложение запускает
программную отрисовку с непрозрачным корпусом и спектром на Canvas.
Для её проверки есть аргумент `--software-rendering` и тест
`soundbar.overlay-software`.

«Преломлять фон рабочего стола» включает Windows Graphics Capture для
монитора, на котором виден док. Захват по умолчанию выключен. Источник
передаёт кадры Direct3D 11 в шейдер через видеокарту. Если Windows Capture
не принимает устройство Qt, используется отдельное устройство с неблокирующим
чтением нужной области. Приложение опрашивает источник примерно 60 раз в секунду
и показывает частоту поступающих кадров в настройках.
Док исключается из снимков экрана на время захвата. Кадры остаются в памяти
программы. При сворачивании стеклянного корпуса, отключении эффекта или
переходе в полноэкранный режим сессия захвата закрывается. При ошибке
док продолжает использовать обычное стекло и показывает состояние в настройках.
Кнопка «Скрыть жёлтую рамку» запрашивает разрешение Windows на захват без границы.
Системные материалы DWM подходят для обычного фона. Для шейдера преломления
используется изображение из Windows Graphics Capture.

Интерактивная приёмка на Windows 11. Включить эффект через «Оформление дока…»
и передвинуть яркое окно за доком. Проверить совпадение изображения при
100%, 150% и 200% масштаба, при смене основного монитора и отключении второго.
Несколько раз открыть настройки, переключить полноэкранный режим и убедиться,
что индикатор захвата исчезает, затем возвращается вместе с доком. Сравнить
нагрузку процесса в Task Manager со включённым и выключенным эффектом.

## 8. Сборка и распространение

[Windows x64 CI](../.github/workflows/windows.yml) собирает приложение MSVC и Qt,
выполняет CTest и разворачивает библиотеку Visual C++ и компоненты Qt рядом
с `.exe`. Из одной папки формируются переносимый ZIP и установщик NSIS.
Артефакт сборки включает архив исходников. Тест поставки запускает обе копии
без Qt SDK в `PATH` и проверяет обновление и удаление.

Установщик работает для текущего пользователя. Он добавляет ярлык в меню
«Пуск» и запись в «Установленных приложениях». Для обновления закройте док
и запустите новый установщик. Настройки и данные лежат в профиле Windows.
Остаётся проверить Windows Graphics Capture и поставку в интерактивной
сессии Windows 11 с реальной видеокартой.

Первый результат — автономный `.exe` со сценой на тестовых данных. Первая
рабочая версия — собственное окно со спектром системного звука, медиакнопками,
локальной лирикой, настройками и треем. Онлайн-лирика, запись Spotify,
анализ и динамическое преломление получают отдельные проверки при переносе.

Живые обои и питомец на рабочем столе образуют отдельный этап. Лирический
огонёк входит в перенос саундбара. Интеграция обоев с рабочим столом Windows
требует своего проекта проверки и не нужна для первого релиза саундбара.
